# Web API (v1.4.0+)

A FastAPI-based REST + WebSocket layer on top of pyquotex. Single-tenant
— one shared `Quotex` client lives for the lifetime of the server and
serves every request — so it's the right fit for an internal trading
service or a strategy bot that needs to expose a clean HTTP/WebSocket
interface without re-implementing the broker glue every time.

## Install

```bash
pip install 'pyquotex[webapi]'
```

The `webapi` extra pulls in `fastapi`, `uvicorn[standard]`, and
`pydantic` — kept optional so the core library has no FastAPI
dependency.

## Run locally

```bash
export PYQUOTEX_EMAIL='you@example.com'
export PYQUOTEX_PASSWORD='…'
export PYQUOTEX_API_KEY='generate-a-long-random-string-here'
export PYQUOTEX_ACCOUNT_MODE='PRACTICE'   # or REAL

python -m pyquotex.webapi
```

Then browse:

- **Swagger UI** — http://localhost:8000/docs
- **OpenAPI schema** — http://localhost:8000/openapi.json
- **Health probe** — http://localhost:8000/health (no auth)

## Run in Docker

`docker-compose.yml` is in the repo root.

```bash
cp .env.example .env   # or just export the vars
docker compose up --build
```

The image runs as a non-root user, exposes `:8000`, and ships with a
container-level `HEALTHCHECK` that hits `/health`.

## Auth

Every endpoint except `/health` requires a single API key. Send it in
either header:

```
X-API-Key: <PYQUOTEX_API_KEY>
Authorization: Bearer <PYQUOTEX_API_KEY>
```

For WebSocket upgrades from a browser (where custom headers aren't
allowed), pass it as a query string instead:

```
ws://localhost:8000/stream/prices?asset=EURUSD_otc&api_key=<…>
```

A wrong/missing key returns `401` for REST or closes the WebSocket
with code `1008` (policy violation).

## REST endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Readiness probe — connection state + reconnect stats. No auth. |
| `POST` | `/auth/connect` | Warm the broker WebSocket; returns balance + profile. |
| `GET` | `/account/balance` | Cached balance + currency. |
| `GET` | `/account/profile` | Profile fields (nickname, currency, timezone, balances). |
| `GET` | `/market/candles` | Recent candles (broker-capped at ~200 per request). Query: `asset`, `period`, `offset`, `end_from_time`. |
| `GET` | `/market/historical-candles` | Deep history via parallel-stitched workers. Query: `asset`, `period`, `amount_of_seconds`, `max_workers` (≤10). |
| `GET` | `/market/sentiment/{asset}` | Current trader sentiment. |
| `POST` | `/trades/buy` | Place an immediate trade. |
| `POST` | `/trades/pending` | Time-based pending order. |
| `POST` | `/trades/pending-at-price` | Quote-triggered pending (experimental). |
| `GET` | `/trades/{order_id}/result` | Long-poll for the settled outcome. |
| `DELETE` | `/trades/{order_id}` | Sell early (cancel). |

### Quick recipes

**Place a trade and wait for the result:**

```bash
TOKEN='your-api-key'

# Place a $1 call on EURUSD for 60s
TRADE=$(curl -s -X POST http://localhost:8000/trades/buy \
  -H "X-API-Key: $TOKEN" -H "Content-Type: application/json" \
  -d '{"amount":1,"asset":"EURUSD_otc","direction":"call","duration":60}')

ID=$(echo "$TRADE" | python -c 'import sys,json;print(json.load(sys.stdin)["order_id"])')

# Long-poll the result (event-driven; wakes the moment the broker settles)
curl -s "http://localhost:8000/trades/$ID/result?duration=60&timeout=90" \
  -H "X-API-Key: $TOKEN"
# → {"order_id":"…","status":"win","profit":0.93}
```

**Place a time-based pending and follow its lifecycle:**

```bash
PEND=$(curl -s -X POST http://localhost:8000/trades/pending \
  -H "X-API-Key: $TOKEN" -H "Content-Type: application/json" \
  -d '{"amount":1,"asset":"EURUSD_otc","direction":"call","duration":60}')

PID=$(echo "$PEND" | python -c 'import sys,json;print(json.load(sys.stdin)["pending_id"])')

# /trades/{id}/result also works for pending tickets — the lifecycle
# bridge mirrors the executed-trade close back onto the pending ticket.
curl -s "http://localhost:8000/trades/$PID/result?duration=60&timeout=180" \
  -H "X-API-Key: $TOKEN"
```

## WebSocket streams

| Path | Stream |
| --- | --- |
| `WS /stream/prices?asset=…&api_key=…` | Live price ticks. |
| `WS /stream/sentiment?asset=…&api_key=…` | Live trader-sentiment updates. |

Each frame is a JSON object. Subscribers receive deltas as the broker
emits them. Backpressure is handled at the relay: if a slow client
falls behind the per-subscriber queue cap, the **oldest** tick is
dropped to make room (the broker never blocks on a slow consumer).

A single broker subscription is multiplexed across all WebSocket
clients listening to the same asset. When the last client disconnects,
the upstream subscription is dropped automatically.

### Wire format

`/stream/prices`:

```json
{"asset": "EURUSD_otc", "time": 1746450123, "price": 1.0852}
```

`/stream/sentiment`:

```json
{
  "asset": "EURUSD_otc",
  "bullish": 0.62,
  "bearish": 0.38,
  "raw": {"bullish": 62, "bearish": 38}
}
```

Errors:

```json
{"error": "…", "asset": "EURUSD_otc"}
```

### Python client snippet

```python
import asyncio, json, websockets

URL = "ws://localhost:8000/stream/prices?asset=EURUSD_otc&api_key=…"

async def main():
    async with websockets.connect(URL) as ws:
        for _ in range(10):
            tick = json.loads(await ws.recv())
            print(tick["time"], tick["price"])

asyncio.run(main())
```

## Long-polling for trade results

`GET /trades/{id}/result?duration=…&timeout=…` blocks server-side on
`Quotex.wait_for_order_close`, which is **event-driven** — it returns
the moment the broker emits the close payload, not after a poll cycle.

| Outcome | Response |
| --- | --- |
| Trade settled | `{"order_id":"…","status":"win"|"loss","profit":<float>}` |
| Deadline exceeded | `{"order_id":"…","status":"timeout","profit":0.0}` (HTTP 200) |
| Broker error | `502` with the underlying message |

Default deadline is `PYQUOTEX_RESULT_POLL_TIMEOUT` (90 s). Override per
request with the `timeout` query param (max 600 s).

## Configuration

All env-var driven; see `pyquotex/webapi/config.py`.

| Variable | Default | Purpose |
| --- | --- | --- |
| `PYQUOTEX_EMAIL` | required | Broker login. |
| `PYQUOTEX_PASSWORD` | required | Broker password. |
| `PYQUOTEX_API_KEY` | required | Bearer token for the web API. **Refuses to start without it.** |
| `PYQUOTEX_ACCOUNT_MODE` | `PRACTICE` | `PRACTICE` (demo) or `REAL`. |
| `PYQUOTEX_LANG` | `en` | Broker UI language. |
| `PYQUOTEX_HOST` | `0.0.0.0` | Bind interface. |
| `PYQUOTEX_PORT` | `8000` | Bind port. |
| `PYQUOTEX_CORS_ORIGINS` | `*` | Comma-separated allow-list (or `*`). |
| `PYQUOTEX_RESULT_POLL_TIMEOUT` | `90` | Default deadline (s) for `/trades/{id}/result`. |
| `PYQUOTEX_RELAY_POLL_INTERVAL` | `0.1` | How often the WebSocket relay flushes new ticks (s). |
| `PYQUOTEX_RELAY_QUEUE_MAX` | `100` | Per-subscriber queue cap (oldest evicted on overflow). |

## Operational notes

- **Single-tenant.** One shared `Quotex` client = one broker account.
  For multi-account, run one container per account behind a shared
  reverse proxy + per-account API keys.
- **Auto-reconnect** is on by default (`auto_reconnect=True` on
  `Quotex(...)`). The supervisor reconnects on drops with exponential
  backoff and replays subscriptions, so the API stays available
  through transient broker drops without callers noticing.
- **Rate limits / bans.** Broker ban risk goes up with `max_workers`
  on `/market/historical-candles`. Stick to ≤ 5 for routine pulls.
- **Long-running ops.** `/trades/{id}/result` can block for the full
  trade duration. Make sure your reverse proxy / load balancer's
  request timeout is **higher** than `PYQUOTEX_RESULT_POLL_TIMEOUT`.
- **Health probe.** `/health` returns `200` even when the broker is
  unreachable (for container readiness purposes); inspect
  `body.connected` to distinguish.
