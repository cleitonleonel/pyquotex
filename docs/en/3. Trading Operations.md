# Trading Operations Documentation - PyQuotex

## 1. Simple Buy Operation

The simple buy operation allows performing a basic transaction by specifying the amount, asset, direction, and duration.

```python
async def buy_simple():
    amount = 50  # Amount in account currency
    asset = "AUDCAD"  # Asset code
    direction = "call"  # Direction: "call" (up) or "put" (down)
    duration = 60  # Duration in seconds
    
    status, buy_info = await client.buy(amount, asset, direction, duration)
    # status: True/False indicating if operation was successful
    # buy_info: Detailed order information
```

## 2. Buy with Result Verification

This operation allows making a purchase and automatically waiting for the result:

```python
async def buy_and_check_win():
    amount = 50
    asset = "EURUSD_otc"
    direction = "call"
    duration = 60
    
    status, buy_info = await client.buy(amount, asset, direction, duration)
    if status:
        # Wait for the result (The internal timer is synchronized with the Quotex server)
        # check_win now returns a tuple: (win_status, profit)
        win_status, profit = await client.check_win(buy_info["id"])
        
        if win_status == "win":
            print(f"Win! Profit: {profit}")
        else:
            print(f"Loss. Result: {profit}")
```

## 4. Pending Orders

Pending orders schedule a trade to fire either at a future time or
when the price reaches a level. Verified end-to-end against
`ws2.qxbroker.com` in v1.2.0.

### 4.1 Time-based pending — `open_pending()`

```python
async def buy_pending():
    # Auto-schedule: fires at the next 60-second boundary at least
    # 90 s ahead, in your profile's local time.
    status, info = await client.open_pending(
        amount=1,
        asset="EURUSD_otc",
        direction="call",         # "call"/"put" or "up"/"down"
        duration=60,              # resulting trade duration in seconds
        open_time=None,           # None → auto-schedule
        confirm_timeout=30.0,     # how long to wait for the broker ACK
    )
    print(status, client.api.pending_id)
```

To pick a specific time, pass `open_time` as a local string:

```python
status, info = await client.open_pending(
    amount=1, asset="EURUSD_otc", direction="call",
    duration=60,
    open_time="16/12 15:51",   # "DD/MM HH:MM"  (your profile timezone)
)
```

The wrapper normalises it through your profile's UTC offset and
emits an ISO 8601 string on the wire. The broker rejects raw integer
times with `{"error": "open_time_min"}` regardless of how far ahead
they point — `pyquotex` v1.2+ never sends an integer.

### 4.2 Quote-triggered pending — `open_pending_at_price()`

> **Experimental** — only time-based mode has been verified end-to-end.

```python
status, info = await client.open_pending_at_price(
    amount=1, asset="EURUSD_otc", direction="call",
    quote=1.0852, period="M1",
)
```

### 4.3 Tracking the result

The broker emits `f_pending/opened` (pre-fire), `s_pending/opened`
(success), and `s_orders/close` (settlement) when a pending fires.
`pyquotex` mirrors the close back onto the pending ticket so
`check_win()` works the same way as for instant trades:

```python
status, info = await client.open_pending(
    amount=1, asset="EURUSD_otc", direction="call", duration=60,
)
# … wait for openTime …
result, profit = await client.check_win(client.api.pending_id, duration=60)
print(result, profit)         # e.g. ("win", 0.93)
```

See [Advanced Features → Pending Orders](12.%20Advanced%20Features#pending-orders-time-based-and-quote-triggered)
for the full wire-shape reference and the lifecycle diagram.

## 5. Selling Options

Allows closing a position before expiration:

```python
async def sell_option():
    # First open a position
    status, buy_info = await client.buy(amount, asset, direction, duration)
    
    # Then sell the option using its ID
    result = await client.sell_option(buy_info["id"])
```

## 6. Result Verification

`v1.2.0` adds an event-driven helper that wakes the moment the
broker emits the close payload — no more 200ms polling cycles.

### 6.1 Event-driven (preferred) — `wait_for_order_close()`

```python
async def check_result(operation_id):
    # Returns (status, profit) within milliseconds of the close.
    # ``status`` is "win" or "loss"; ``profit`` is float (negative on loss).
    status, profit = await client.wait_for_order_close(
        operation_id, duration=60,
    )
```

`check_win(operation_id)` is the underlying canonical name and
behaves identically; the helper above is a clearer alias.

### 6.2 HTTP history — `get_result()`
```python
async def check_result(operation_id):
    status, operation_info = await client.get_result(operation_id)
    # status: "win" or "loss"
    # operation_info: complete operation details
```

### 6.2 Real-time verification (Event-Driven)
```python
async def check_win(id_number):
    # Returns a tuple (win_status, profit)
    # win_status: "win" or "loss"
    # profit: The profit/loss amount
    status, profit = await client.check_win(id_number)
    return status == "win"
```

## Important Considerations

1. All operations are asynchronous and require the use of `await`
2. It's recommended to verify that the asset is available before trading
3. Expiration times are in seconds
4. Valid directions are "call" (up) and "put" (down)
5. Always verify connection status before operating
6. It's important to handle errors properly in production
